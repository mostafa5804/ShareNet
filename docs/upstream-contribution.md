# مشارکت با پروژه اصلی zeptun

ShareNet از [Noisemux/zeptun](https://github.com/Noisemux/zeptun) به‌عنوان موتور
تونل شبکه استفاده می‌کند. مجوز MIT اجازه استفاده، تغییر و توزیع را می‌دهد،
مشروط به حفظ اعلان مجوز.

## چه چیزی برای PR به upstream مناسب است؟

- رفع باگ عمومی در خود zeptun که مستقل از رابط ShareNet قابل بازتولید باشد؛
- بهبود Windows، Wintun، CLI یا مستندات عمومی zeptun؛
- تستی که رفتار موتور را در یک سناریوی عمومی پوشش دهد.

رابط فارسی، کنترل پنل مودم، ذخیره تنظیمات ShareNet و گردش‌کار DHCP ویژگی‌های
این پروژه‌اند و معمولاً نباید به‌صورت یک PR بزرگ به zeptun ارسال شوند؛ مگر
نگهدارنده upstream صریحاً چنین ادغامی را بخواهد.

## گردش‌کار پیشنهادی

1. آخرین شاخه اصلی zeptun را fork و بررسی کنید.
2. مشکل را ابتدا در خود zeptun، بدون ShareNet، بازتولید کنید.
3. تغییر را کوچک، عمومی و همراه تست یا مراحل بازتولید نگه دارید.
4. تست‌های اعلام‌شده در README پروژه اصلی را اجرا کنید.
5. Issue یا Pull Request را با توضیح رفتار فعلی، رفتار مورد انتظار و محیط
   Windows باز کنید.
6. ShareNet را فقط به‌عنوان نمونهٔ استفاده ذکر کنید؛ ادغام PR در اختیار
   نگهدارندگان zeptun است.

پیش از ارسال، راهنمای مشارکت و Issueهای فعلی upstream را دوباره بررسی کنید؛
ساختار و سیاست‌های پروژه اصلی ممکن است تغییر کند.
