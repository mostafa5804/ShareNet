# ShareNet Gateway v1

ShareNet یک ابزار متن‌باز Windows است که ترافیک دستگاه‌های یک شبکه محلی را از
یک SOCKS5 فعال روی کامپیوتر عبور می‌دهد. نسخه ۱ رابط گرافیکی دارد و تغییرات
Windows و DHCP مودم را با پیش‌نمایش، read-back و امکان بازگردانی انجام می‌دهد.

## موتور شبکه و پروژه اصلی zeptun

ShareNet برای ساخت تونل شبکه در Windows از موتور متن‌باز
[Noisemux/zeptun](https://github.com/Noisemux/zeptun) استفاده می‌کند و فایل
`zeptun.exe` را همراه برنامه توزیع می‌کند. zeptun تحت مجوز MIT منتشر شده است؛
متن مجوز آن در [vendor/zeptun/LICENSE](vendor/zeptun/LICENSE) و مشخصات دقیق
اجزای ثالث در [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) قرار دارد.

ShareNet یک رابط و ابزار مستقل برای تنظیم Windows و DHCP مودم است و در وضعیت
فعلی محصول رسمی یا مورد تأیید نویسندگان zeptun نیست. اگر در جریان توسعه بهبود
عمومی و مستقلی برای خود موتور zeptun ایجاد شود، از ارسال آن به شکل Issue/PR
کوچک و قابل‌آزمایش به upstream استقبال می‌کنیم. راهنمای این کار در
[مشارکت با پروژه اصلی](docs/upstream-contribution.md) آمده است.

> **محدوده نسخه ۱:** Windows 10/11 x64. تنظیم خودکار مودم فعلاً مخصوص پنل
> انگلیسی TP-Link Archer C80 است؛ برای سایر مودم‌های سازگار حالت
> `Other Router — Manual Setup` وجود دارد.

## هشدار مهم

این برنامه IP، routing، forwarding و تنظیمات DHCP مودم را تغییر می‌دهد و در
صورت تنظیم اشتباه می‌تواند موقتاً اینترنت شبکه را قطع کند. پیش از فعال‌سازی،
حتماً `Dry Run` را بررسی کنید. گزینه «غیرفعال‌سازی و بازگردانی» مقادیر ذخیره‌شده
را برمی‌گرداند.

## Quick Start

1. از صفحه Releases فایل `ShareNet-v1.0.0-Windows-x64.exe` را دانلود کنید.
2. VPN/Proxy خود را وصل کنید و مطمئن شوید SOCKS5 محلی فعال است؛ مقدار پیش‌فرض
   `127.0.0.1:10808` است.
3. EXE را اجرا و درخواست Administrator ویندوز را تأیید کنید.
4. روش مودم را انتخاب کنید؛ Archer C80 خودکار است و سایر مدل‌ها حالت دستی دارند.
5. «تشخیص خودکار شبکه»، سپس «تست مودم/راهنمای مودم» را بزنید.
6. در حالت خودکار رمز مودم را وارد کنید. در صورت انتخاب گزینه ذخیره، رمز فقط در Windows
   Credential Manager ذخیره می‌شود و داخل `config.json` نوشته نمی‌شود.
7. `Dry Run` را اجرا و تغییرات پیشنهادی را کنترل کنید.
8. «فعال‌سازی» را بزنید؛ سپس Wi-Fi دستگاه مقصد را یک‌بار خاموش و روشن کنید.

اگر مودم Archer C80 نیست، از فهرست «روش تنظیم مودم» گزینه
`Other Router — تنظیم دستی` را انتخاب کنید. در این حالت رمز مودم لازم نیست و
ShareNet بعد از فعال‌سازی، Gateway و DNS لازم را برای ورود دستی در DHCP Server
نمایش می‌دهد. ترتیب کامل در [راهنمای تنظیم دستی](docs/manual-router-setup.md)
آمده است.

برای پایان کار، «غیرفعال‌سازی و بازگردانی» را بزنید. کامپیوتر باید هنگام اشتراک
روشن و بیدار بماند.

پس از ساخت `.venv` و نصب وابستگی‌ها، برای اجرای سورس کافی است روی
`RUN_APP.bat` دوبار کلیک کنید. اجرای مستقیم `python launcher.py` نیز ممکن است و
به‌طور خودکار یک‌بار درخواست UAC نمایش می‌دهد. در صورت خطا، اجرای BAT پنجره را
باز نگه می‌دارد تا پیام خطا قابل مشاهده باشد.

## داده‌ها کجا ذخیره می‌شوند؟

فایل‌های محلی در این مسیر قرار می‌گیرند:

```text
%LOCALAPPDATA%\ShareNet\
├── config.json              تنظیمات غیرحساس
├── router_backup.json       نسخه پشتیبان DHCP مودم
├── _lan_share_state.json    وضعیت شبکه پیش از تغییر
├── logs\                    لاگ محلی
└── runtime\                 موتور و فایل‌های اجرایی لازم
```

رمز در این پوشه ذخیره نمی‌شود. برای حذف رمز ذخیره‌شده می‌توانید Windows
Credential Manager را باز کرده و ورودی `ShareNet Gateway` را حذف کنید.

## تنظیمات

| فیلد | توضیح |
|---|---|
| آدرس پنل مودم | معمولاً Default Gateway؛ مانند `http://192.168.1.1` |
| نام کاربری | در firmwareهایی که فقط رمز می‌خواهند استفاده نمی‌شود |
| IP مودم | Gateway واقعی شبکه محلی |
| محدوده LAN | نمونه: `192.168.1.0/24` |
| IP ثابت کامپیوتر | باید خارج از DHCP pool و داخل LAN باشد |
| SOCKS5 | پروکسی محلی فعال روی همین کامپیوتر |

مقادیر غیرحساس در رابط برنامه یا `%LOCALAPPDATA%\ShareNet\config.json` قابل
تغییرند و برای تغییر آن‌ها نیازی به build مجدد EXE نیست.

متغیرهای محیطی اختیاری برای اجرای خودکار در `.env.example` معرفی شده‌اند.
خود برنامه فایل `.env` را بارگذاری نمی‌کند؛ متغیرها باید توسط محیط اجرا تنظیم
شوند. از ثبت رمز واقعی در فایل‌های Git خودداری کنید.

## سازگاری مودم‌ها

فهرست مدل‌ها و روش تشخیص سازگاری در
[راهنمای سازگاری مودم‌ها](docs/router-compatibility.md) قرار دارد. وجود فیلد DNS
به‌تنهایی کافی نیست؛ DHCP Server باید اجازه تغییر Default Gateway را هم بدهد.

## Dry Run و بازگردانی

Dry Run به مودم به‌شکل read-only متصل می‌شود و موارد زیر را نشان می‌دهد:

- Gateway و DNS فعلی DHCP؛
- IP پیشنهادی کامپیوتر؛
- آدرس SOCKS5 و دسترس‌پذیری آن؛
- تغییراتی که در مرحله Apply انجام می‌شوند.

در فعال‌سازی، ابتدا مقادیر مودم و وضعیت Windows ذخیره می‌شوند. اگر تغییر مودم
شکست بخورد، برنامه تغییرات Windows را بازمی‌گرداند. با وجود این، در صورت قطع
برق یا crash سیستم ممکن است نیاز باشد DHCP کارت شبکه یا مودم را دستی فعال کنید.

## عیب‌یابی

| مشکل | اقدام |
|---|---|
| SOCKS5 در دسترس نیست | VPN/Proxy را متصل و host/port را بررسی کنید |
| صفحه DHCP پیدا نشد | مدل، firmware یا زبان پنل پشتیبانی نمی‌شود |
| دسترسی Administrator رد شد | برنامه نمی‌تواند IP و forwarding را تغییر دهد |
| اینترنت دستگاه‌ها قطع شد | «غیرفعال‌سازی و بازگردانی» را اجرا کنید |
| برنامه بسته شد و شبکه برنگشت | Windows را روی DHCP و DHCP مودم را روی مقادیر قبلی برگردانید |

برای گزارش مشکل، از داخل برنامه «خروجی عیب‌یابی پاک‌سازی‌شده» را بسازید. حتی
پس از پاک‌سازی خودکار، قبل از ارسال ZIP آن را شخصاً بازبینی کنید.

## ساخت EXE روی Windows

```powershell
git clone https://github.com/YOUR_ACCOUNT/ShareNet.git
cd ShareNet
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Clean
```

خروجی در `dist\ShareNet-v1.0.0-Windows-x64.exe` قرار می‌گیرد. Microsoft Edge
باید روی سیستم مقصد نصب باشد؛ نسخه ۱ برای کنترل پنل مودم از Edge موجود در
Windows استفاده می‌کند و مرورگر جداگانه داخل EXE بسته‌بندی نمی‌شود.

## ساخت خودکار Release با Tag

پس از push کردن repository:

```bash
git tag v1.0.0
git push origin v1.0.0
```

Workflow فایل `.github/workflows/release.yml` تست‌ها را اجرا، EXE را build،
فایل `SHA256SUMS.txt` را تولید و GitHub Release را ایجاد می‌کند.
